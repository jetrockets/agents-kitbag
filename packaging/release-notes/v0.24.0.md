Claude Toolkit is now **Agents Kitbag**.

The app is growing past MCP servers for one assistant, toward everything an AI assistant is equipped with, for more than one of them. The old name said too little about that and borrowed someone else's.

## This is a new app, not an update

Agents Kitbag has its own name, files and identity, so a copy of Claude Toolkit will not update itself to it. Install Agents Kitbag once, by hand; from then on it updates itself. Then delete Claude Toolkit.

- **macOS:** open `agents-kitbag-v0.24.0-macos-universal.dmg` and drag Agents Kitbag to Applications. Not signed with an Apple Developer ID yet: the first time, right-click, Open, Open.
- **Windows:** unpack `agents-kitbag-v0.24.0-x86_64-pc-windows-msvc.zip` into a folder that will stay and run `agents-kitbag.exe`.
- **Linux:** unpack `agents-kitbag-v0.24.0-x86_64-unknown-linux-gnu.tar.gz` and run `./install.sh`.

## What carries over, and what does not

- **Your servers stay** in Claude Desktop's config. Those whose token is in the Keychain, DPAPI or the Secret Service were started through a program inside Claude Toolkit: Agents Kitbag shows them with a **Migrate** button that points them at its own.
- **Tokens Claude Toolkit put in the macOS Keychain or the Linux Secret Service stay where they are** and keep working after Migrate. New ones are stored under Agents Kitbag's name (`agents-kitbag-<server>`). On Windows the DPAPI store moved to `%APPDATA%\agents-kitbag\secrets`: set those servers up again.
- **Not carried over:** the log and its folder (Agents Kitbag keeps its own).

## New

- **Claude Code and Codex.** The list at the top of the window chooses whose MCP servers are shown: Claude Desktop, Claude Code (`~/.claude.json`, every project) or Codex (`~/.codex/config.toml`). Each has servers, tokens and backups of its own, and everything else in those files is left as it was. Checked on macOS with the real `claude` and `codex` starting a server the app set up.
- **One Save for several assistants.** The setup form offers the other assistants on this machine under "Set up for"; each gets its own copy of the token. An assistant that was never used on this machine is listed as not installed.
- **A rail of sections.** The window is three columns: sections, the selected section's list, its detail. MCP servers is the first section; the settings sit at the bottom of the rail.
- **A server the service hosts itself** (reached by URL, like Figma's in a Codex config) is shown as what it is: nothing to check, no token kept here, and no button that would replace it.
- **An icon and colours of its own.** A kitbag on graphite, and neutral greys in the window: the app serves several assistants and wears the colours of none.
- Settings open on the version and the update check.

## Fixed

- **macOS Keychain: a long token was cut to 128 characters.** The form said "connected" and the server then got a token the service refused. Jira's tokens are that long. Tokens stored before this release are still cut: use Replace token.
- **A config kept its permissions and its link.** Saving reset a private config (Codex's is owner-only) to the default permissions and replaced a linked config with a plain file.
- **1Password: saving the same server twice no longer breaks it.** The reference names the item by id, so a second item with the same title cannot make it ambiguous.
- A server whose token is not in the store, or whose 1Password is locked, is no longer shown green.
- A token is stored only after the server's package is known to install and the config to be readable, so a failed Save leaves no secret behind.
- The system's store is not offered, or chosen by default, when the runner is missing.
- A command that waits for a person who is not there (1Password locked, a Keychain dialog) is given up on after two minutes instead of holding everything behind it.
- Windows: a runner that is ended takes its server with it. Compiled and tested in CI, not on a desktop.
- GitHub: a 403 for a rate limit or single sign-on is not reported as an expired token.
- Claude Code's config is written under a lock beside it, the kind Claude Code's own lock library takes, so the app and a running session are less likely to lose each other's writes.
- Jira on your own server under a path (`https://host/jira`), and Azure DevOps at `org.visualstudio.com`, are understood.
- "Restart Claude" says so when Claude Desktop did not quit, instead of "restarted".
- The log file holds the app's own lines again; since the rename it held only the first.
- Smaller ones: a non-Unicode environment variable no longer stops the runner, the migration notice no longer blames the Node runner for everything, "Check all tokens" is dim when there is nothing to check.

## How far it was checked

macOS: by hand in the real window, with real tokens in the Keychain and in 1Password, and with Claude Code and Codex starting the servers. Windows and Linux: the tests, the system credential store and a server set up and started on hosted machines, and the window drawn there. Nobody has clicked through the window on Windows or Linux yet.

## For people who build it

The crates are `agents-kitbag-core`, `agents-kitbag-app` and `agents-kitbag-runner`; the programs `agents-kitbag` and `agents-kitbag-runner`; the bundle `com.jetrockets.agents-kitbag`; the repository `jetrockets/agents-kitbag`. The update-signing key is the same.
